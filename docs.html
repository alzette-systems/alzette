The pilot reference for the Alzette inference endpoint: enough to connect, evaluate, and operate. The complete reference, with usage records and account management, ships with the client dashboard.

The endpoint

Connection

Alzette exposes an OpenAI-compatible API. Applications that already work with the OpenAI SDK or a standard HTTP client connect by changing the base URL and the API key. No rewrite.

base_urlhttps://api.alzette.lu/v1
compatibilityOpenAI API: chat completions, streaming, structured output, embeddings
hostingLuxembourg; contractual residency is defined in the service agreement
retentionPrompt and response content is not retained by default; policy defined per environment

Authentication

Credentials

Requests authenticate with a bearer API key. Keys are issued per organisation and project during onboarding, and are isolated per tenant; quotas, usage records, and model access are scoped to your credentials.

Store the key in an environment variable and never in source code:

Environment
export ALZETTE_API_KEY="alz-…"

Quickstart

First request

cURL

HTTP
curl https://api.alzette.lu/v1/chat/completions \
  -H "Authorization: Bearer $ALZETTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "approved-text-model",
    "messages": [{"role": "user", "content": "Summarise this document."}]
  }'

Python

Python · OpenAI SDK
import os

from openai import OpenAI

client = OpenAI(
    base_url="https://api.alzette.lu/v1",
    api_key=os.environ["ALZETTE_API_KEY"],
)

response = client.chat.completions.create(
    model="approved-text-model",
    messages=[
        {"role": "user", "content": "Summarise this document."}
    ],
)

print(response.choices[0].message.content)

Limits and metering

Budgets

Usage is metered by tokens and other agreed resources. Budgets and rate limits are set per organisation and per project, and hard monthly caps stop usage at the agreed limit, so your account cannot spend beyond it.

Specific limits, quotas, and metering detail are defined per service agreement and reviewed during onboarding.

Errors

Failure handling

Error responses follow the OpenAI error format, with standard HTTP status codes. Client code written against the OpenAI SDK handles them without changes.

Requests rejected by a budget cap or rate limit fail visibly at the API. They are never silently degraded or rerouted to a different model.

Changes and support

Operations

Models are served as versioned releases. Changes to model versions, capacity, or operational procedures are communicated in advance, per the change-control terms of the service agreement.

Technical questions go to the same people who operate the service: hello@alzette.lu. A security pack and operational evidence for your compliance review are available on request.
